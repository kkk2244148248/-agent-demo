## 1. 一句话对比

## 3. 新增的 7 个核心机制

| 机制 | 解决什么 | 谁最关心 |
|---|---|---|
| **客户公海 / 私海** | 客户资产归属公司，不是业务员个人；30 天不跟进自动回收 | 老板 |
| **报价底价管控** | 低于底价强制老板特批 + 留痕，防飞单防乱价 | 老板 |
| **报价版本化** | 客户改 5 轮，能看清"为什么没成" | 业务员 |
| **生产跟单节点 + 交期红绿灯** | 一眼看到哪张单要炸 | 业务员 |
| **收款账期 + 催款提醒** | 谁还没打钱，逾期自动揪出来 | 业务员 + 老板 |
| **成本真实毛利** | 算清含退税/汇率后到底赚多少 | 双方 |
| **离职一键交接** | 业务员走了，客户和证据链全留下 | 老板 |

## 4. 多 Agent：7 → 11

**保留并重新站位**：sourcing（找厂比价）、communication（中英邮件）、sample（打样）、compliance（认证单证）、document（识文档）、crm（客户档案）、knowledge（报价口径）

**新增 4 个（跑单专属）**：

| 新 Agent | 解决业务员的什么痛 |
|---|---|
| **profit_agent 成本毛利** | "这单到底赚多少？我报这个价行不行？" |
| **tracking_agent 跟单盯梢** | "我手上 12 张单，哪张要炸了？" |
| **collection_agent 催款** | "谁还没打钱？我不好意思催" |
| **radar_agent 客户雷达** | "老客户 3 个月没动静，是不是要跑了？" |

**架构上唯一的实质改动**：加一层**定时任务**（每天早上 08:30 跑一次扫描 → 生成"今日跑单"卡片）。不需要消息队列，APScheduler 就够。

## 6. 三期路线图

| 期 | 时间 | 目标 | 内容 |
|---|---|---|---|
| **P0 跑单闭环补全** | 3–5 周 | 业务员能在系统里跑完一整单 | 客户归属公海私海 + 报价版本化与毛利底价 + 收款账期 + 生产跟单 + 工厂库界面 |
| **P1 让业务员离不开** | 4–6 周 | 每天第一件事就是打开它 | 每日 08:30 主动推送 + 客户雷达 + 双语 PI/单证 + 我的业绩提成 + 邮件自动建档 |
| **P2 管住风险规模化** | 5–8 周 | 老板放心用 | 团队看板 + 离职交接 + PostgreSQL + 移动端 |

**只做三件事**：① 今日跑单 → ② 成本毛利 + 报价底价 → ③ 客户公海私海 + 离职交接

## 7. 北极星指标

**业务员人均月毛利**（不是订单数——订单多但亏钱没有意义）

诊断口诀：
- `询盘 → 报价率 < 75%` → 业务员响应慢或不会报
- `跟进逾期 > 3 条/人` → 跟进节奏失控
- `客户沉默 > 30 天` → 客户资产在流失

---

## 8. 老板最该关心的三句话

1. **这套系统的价值不在"AI 多聪明"，在"业务员会不会漏事"** —— 今日跑单 + 交期红绿灯 + 应收提醒，才是留存的关键。
2. **不先做"客户公海私海 + 报价底价留痕"，业务员带走的就不只是客户，还有公司的利润**。
3. **算清一单的真实毛利（含退税、汇率、港杂）比任何花活都值钱** —— 账面赚钱、实际亏钱的单子，外贸公司见得太多了。
