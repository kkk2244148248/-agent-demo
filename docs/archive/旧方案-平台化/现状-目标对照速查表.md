# 现状 → 目标 对照速查表（一页纸）

> 配套：`海贸平台模式重设计蓝图.md` · `海贸B2B平台原型.html`
> 用途：给老板 / 团队 3 分钟看懂"改了什么、为什么改"

---

## 1. 一句话对比

| | 现状（海贸工作台） | 目标（海贸 B2B 撮合平台） |
|---|---|---|
| 本质 | **自家公司的内部工具** | **连接中国供应商与海外买家的平台** |
| 主体数 | 1（我方） | 3（供应商 / 采购商 / 平台）+ 生态服务商 |
| 解决的问题 | 我家业务员处理询盘更快 | 陌生人之间怎么安全找到、谈成、交货、结汇 |
| 闭环终点 | 报价 → 订单 | 报价 → 合同 → 支付 → 生产 → 验货 → 报关 → 物流 → 收货 → 评价 → 复购 |
| 核心资产 | 单据与知识口径 | **撮合效率 + 信用体系 + 履约保障** |
| 靠什么赚钱 | 不赚钱（省人力） | 会员费 + 广告 + 佣金 + 增值服务 + 金融分润 |
| 能不能长大 | 服务一家公司，天花板固定 | 供给与需求双向网络效应，可扩张 |

## 3. 主流程对照

**现状（只有 4 跳）**
```
海外邮件 → 人工建档 → Agent 找厂比价 → 草稿提审批 → 正式报价 → 订单
```

**目标（完整双边闭环）**
```
【供给】入驻认证 → 建店 → 上架SKU ─┐
                                    ▼
【需求】注册 → 搜索/浏览 → 发RFQ → 平台派单 → 供应商抢单报价 → 比价选商
        → 谈判(自动翻译) → 打样 → 签PI → 支付(担保/TT/LC) → 生产
        → 验货 → 报关 → 物流 → 收货 → 放款结汇 → 双向评价 → 复购
【平台】全程审核 / 风控 / 担保 / 仲裁 / 结算 / 看板
```

## 4. 多 Agent 对照（7 → 17）

| 现有 7 个 | 目标 |
|---|---|
| sourcing_agent | 拆成 `buyer_sourcing_agent`（帮买家选商）+ `platform_match_agent`（平台派单引擎） |
| communication_agent | 拆成 buyers/supplier 双侧沟通 Agent（带自动翻译） |
| sample_agent | `trade_sample_agent`（三端共用） |
| compliance_agent | `trade_compliance_agent`（**升格为付费服务**） |
| document_agent | `trade_document_agent`（PI/提单/质检报告） |
| crm_agent | 拆三份（买家/供应商/平台） |
| knowledge_agent | `platform_kb_agent`（内容中台） |
| —— | **新增**：`platform_review_agent`、`platform_risk_agent`、`platform_arbiter_agent`、`supplier_quote_agent`、`fulfillment_agent`、`platform_ops_agent`、`onboarding_agent` |

**不变的两条铁律**：① 审批闸门保留并扩到三端；② 工具解耦、按需调用（MCP 风格）继续用。

## 5. 数据模型对照

| 现状 | 目标 |
|---|---|
| User（员工） | User + **Org（企业主体）** + Membership(org,user,role) |
| Customer（我的客户） | **BuyerOrg**（平台注册买家） |
| Vendor（我的厂商资料卡） | **SupplierOrg + Certification + FactoryAudit**（公开店铺+信用档案） |
| —— | **Product / Sku**（上架商品） |
| Inquiry | **Rfq + RfqDispatch**（加派单与可见性） |
| Quotation | **Quote**（加 supplier_id、报价互不可见） |
| Order | **Order + PiContract + Payment + Shipment + Inspection**（拆履约链） |
| —— | **Review / Dispute / Message / Quota / Billing** |
| Audit | AuditLog + **EvidenceChain**（合规证据链） |

**一条铁律**：所有实体加 `org_id`，供应商**绝不能**看到竞争对手报价。

| 端 | 页面数（估） | 核心页 |

## 7. 三期路线图

| 期 | 时间 | 目标 | 交付物 |
|---|---|---|---|
| **P0 平台骨架** | 4–6 周 | 跑通"买家发RFQ → 供应商报价 → 买家看对比" | 多租户隔离 + 入驻认证 + 上架 + 派单 + 报价 |
| **P1 交易与信任** | 6–10 周 | 真金白银成交 | 合同 + 担保支付 + 履约链 + 评价信用分 + **移动端** |
| **P2 规模与生态** | 10 周+ | 可复制的增长与收入 | 搜索推荐 + 会员广告 + 服务商 + 风控 + 仲裁 + 看板 |

**只做三件事的话**：① 多租户数据隔离 → ② 供应商入驻上架抢单 → ③ 买家发RFQ+报价对比。

## 8. 北极星指标

**月度有效成交订单数（含首单）**

诊断口诀：
- `RFQ → 报价率 < 60%` → 供给不足 / 派单不准
- `报价 → 成交率 < 10%` → 价格 / 信任 / 响应问题

---

## 9. 老板最该关心的三句话

1. **现在这套系统的价值沉淀在"流程"，平台的价值沉淀在"网络"** —— 前者不增长，后者会自我强化。
2. **不先解决多租户隔离，就等于把客户报价摆在对手桌上** —— 这是安全红线，也是平台信任的底线。
3. **冷启动先做供给**：把现有 5 类礼品的 50–100 家工厂用人+Agent 代运营拉进来，保证"每个询盘至少 3 家能报"，再谈流量。
