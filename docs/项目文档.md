## 1. 产品定位与用户

### 1.1 是什么

**海贸工作台**是面向礼品外贸「中国 sourcing 小团队」（约 1–20 人）的**内部员工系统**，把海外询盘处理、国内找厂比价、样品跟进、报价下单、发送审批、知识口径问答，收敛到一个 Web 工作台，并用多 Agent 辅助业务员提效。

### 1.2 不是什么

- 不是面向海外客户的门户 / 自助下单商城  
- 不是完整 ERP / 财务系统  
- 不是「全自动无人值守」外贸机器人（外发仍需人工审批闸门）

### 1.3 目标用户

| 角色 | 典型账号 | 能力 |
|------|----------|------|
| 业务员 | `liht` | 建询盘、跑 Agent、写草稿、跟进、样品 |
| 经理/管理员 | `chenxw` | 业务 + 账号管理（停用离职） |
| 老板/审批 | `zhoum` | 发送审批通过/驳回 |

默认试用密码均为 `123456`（正式环境务必改密）。

### 1.4 核心价值主张

1. **询盘进系统**：少靠 Excel / 微信碎片信息  
2. **Agent 按需干活**：找厂、比价、写邮件、识附件，不是死板流水线  
3. **审批防乱承诺**：AI 草稿不能直接当正式外发  
4. **知识口径统一**：FAQ + RAG，减少「每个人说法不一样」

## 2. 业务能力全景

```
海外 RFQ / 邮件
    → 询盘 Inbox 建档
    →（可选）对话助手 / 智能处理：解析需求、找厂、比价、写回复、识文档
    → 人工改草稿 → 提交发送审批 → 老板决定
    → 正式报价 → 转订单
    ↔ 样品进度、跟进待办、客户/厂商档案、知识问答
```

| 模块 | 前端路由 | 说明 |
|------|----------|------|
| 今日看板 | `/` | 询盘/逾期跟进/样品/报价/订单待办汇总 |
| 对话助手 | `/assistant` | 总控多 Agent 主入口；可上传附件 |
| Skill/工具目录 | `/agents` | 展示 Skill 与底层工具 |
| 需求收件箱 | `/inbox`、`/inbox/:id` | 询盘列表与详情、智能处理、提审批 |
| 发送审批 | `/approvals` | 外发闸门 |
| 跟进 | `/followups` | 待办；逾期标红 |
| 样品 | `/samples` | 打样/寄样；可转订单 |
| 报价 | `/quotations` | 正式报价；可转订单 |
| 订单 | `/orders` | 订单台账 |
| 客户 / 厂商 | `/customers`、`/vendors` | 档案 + related 360 |
| 知识库 | `/knowledge` | 检索 / 重建索引 |
| 审计 / 账号 | `/audit`、`/users` | 操作日志、停用账号 |
| 登录 | `/login` | 公共页 |

悬浮助手（`FloatingChat`）可在各页快速 `POST /api/chat/ask`。

## 3. 系统架构

### 3.1 逻辑分层

```
┌─────────────────────────────────────────────┐
│  Vue3 前端 (:5173)  router + views + api.js │
└─────────────────────┬───────────────────────┘
                      │ HTTP Bearer Token
┌─────────────────────▼───────────────────────┐
│  FastAPI (:8000)  backend/api/app.py        │
│  auth / CRUD / assistant / knowledge        │
└───────┬─────────────┬─────────────┬─────────┘
        │             │             │
   ┌────▼────┐  ┌─────▼─────┐  ┌────▼────┐
   │ Store   │  │ Agent 层  │  │ 知识层  │
   │ JSON    │  │Supervisor │  │ FAQ/RAG │
   └─────────┘  │Skill/Tool │  └───┬─────┘
                └─────┬─────┘      │
                      │            │
         ┌────────────▼────────────▼──────────┐
         │ 千问 LLM / 视觉 · Milvus · Redis   │
         │ MySQL FAQ · 本地 BGE-M3            │
         └────────────────────────────────────┘
```

### 3.2 两条主工作路径

| 路径 | 入口 | 特点 |
|------|------|------|
| **AI 对话线** | `/assistant` → `/api/assistant/chat` | 总控选 Skill → 子 Agent → 工具；可写 CRM、回写询盘 pipeline |
| **业务单据线** | Inbox / 报价 / 订单等页面 | 人工 CRUD；审批后正式外发；可调用旧 `agents/run` / `process` |

两条线最终都写入同一套 `RuntimeStore`（`storage/*.json`）。

### 3.3 Agent 调度（摘要）

```
用户消息 (+ 可选 file_path / inquiry_id)
  → supervisor_select（附件优先 / CRM 优先 / match_skill）
  → domain_agent_select_tools（按 Skill + 启发式裁剪工具）
  → run_selected_tools（顺序执行，pipeline 累积）
  → _format_answer + actions/nav_links
  → 审计；若有 inquiry_id 则写回 pipeline
```

详情见 [MCP式Agent说明.md](./MCP式Agent说明.md) 与 [Agent与工具参数手册.md](./Agent与工具参数手册.md)。

## 6. 后端详解

### 6.1 启动

```bash
cd <项目根>
pip install -r requirements.txt
python run_api.py
```

`run_api.py` 使用 `uvicorn` 加载 `backend.api.app:app`，主机/端口来自配置（默认 `0.0.0.0:8000`）。

### 6.2 关键模块职责

| 模块 | 职责 |
|------|------|
| `api/app.py` | 路由、Depends 鉴权、组装上下文、调 Agent/Store |
| `services/store.py` | 询盘/报价/订单/样品/客户/厂商/跟进/审批/审计 |
| `services/auth.py` | 用户、密码哈希、Token session（约 14 天） |
| `services/doc_parser.py` | PDF/图片解析策略 |
| `agents/supervisor.py` | 大对话总控 |
| `agents/tools/*` | 可调用工具实现 |
| `core/llm_factory.py` | 千问 / Mock LLM |
| `core/knowledge_base.py` | 检索与建库封装 |
| `core/chat_assistant.py` | 悬浮助手：Redis→FAQ→Skill?→RAG |

### 6.3 请求鉴权

除健康检查与登录外，接口通过 `Authorization: Bearer <token>` + `current_user` 依赖注入。Token 无效返回 401；前端清 session 并回登录页。

### 6.4 审计

关键写操作与 Agent 对话会 `store.add_audit(employee, action, target, detail)`，可在「操作审计」页查看。

## 8. 多 Agent 体系

### 8.1 设计原则

- **不是**固定 LangGraph 死流水线  
- **是**「总控选 Skill → 子 Agent 在工具箱内选工具 → 按序执行」  
- 工具彼此解耦，可通过 `/api/agents/{tool_name}` 单独调用，也可透传 `pipeline` 中间结果

### 8.2 七个子 Agent（工具箱规模）

| Agent | 工具数 | 能力摘要 |
|-------|--------|----------|
| sourcing_agent | 6 | 解析、找厂、排序、比价、成本粗算、风险 |
| communication_agent | 6 | 回海外、润色、跟催、待办抽取、询厂 |
| sample_agent | 5 | 列表/登记/逾期/推进状态/打样简报 |
| compliance_agent | 4 | 品类认证、市场单证包、宣传风险、出货单证 |
| document_agent | 3 | OCR、抽报价字段、文档 vs 需求 |
| crm_agent | 5 | 写入、搜索、客户360、逾期跟进、跳转 |
| knowledge_agent | 2 | FAQ + RAG 检索问答 |

全库约 **30** 个工具：`handlers.py`（基础）+ `extended.py`（扩充）+ `crm_actions.py`。

### 8.3 Skill（约 15 个）

YAML 位于 `backend/agents/skills/`。规则匹配优先级（`router._RULE_ORDER`）大致为：

`crm_action` → `doc_parse` → `full_rfq` → `followup_mail` → `email_todos` → `sample_track` → `cert_check` → `vendor_risk` → `cost_estimate` → `ask_factory` → `reply_overseas` → `compare_quotes` → `parse_requirement` → `find_vendor` → `kb_qa`

每个 Skill 含：`id/title/when/triggers/tools/mode`。

### 8.4 公共 context

工具执行时 `call_tool(name, **ctx)`，ctx 通常含：

- 询盘字段：`inquiry_id, customer_name, country, subject, body`  
- 用户话：`query`（来自 message）  
- 累积：`pipeline` 及其中的 `requirement / vendor_match / compare / document…`  
- 附件：`file_path, force_vision`

### 8.5 可选 MCP

```bash
python -m backend.mcp_server.gift_mcp
```

将工具以 MCP 形式暴露（供外部宿主调用，非 Web 主路径必需）。

## 9. 知识库与对话助手

### 9.1 语料与建库

- 语料目录：`data/knowledge/**`（公司介绍、话术、厂商卡片等）  
- 脚本：

```bash
python scripts/init_milvus.py
python scripts/build_knowledge_base.py
```

- 集合名默认 `gift_knowledge`；dense 1024 + sparse；WeightedRanker；父子分块（child 召回 → parent 回填）  
- 详细：[RAG-Milvus父子分块.md](./RAG-Milvus父子分块.md)

### 9.2 悬浮助手链路（`/api/chat/ask`）

1. Redis 命中 → 直接返回  
2. MySQL FAQ + BM25，置信度达标 → 返回并写 Redis  
3. 可识别业务 Skill 时 → 调工具  
4. 否则 RAG + LLM → 返回并写 Redis  

详见：[对话助手-Redis-MySQL-RAG.md](./对话助手-Redis-MySQL-RAG.md)

### 9.3 对话助手页的知识 Agent

`kb_qa` Skill 现走工具：`faq_lookup` → `kb_search`（不再是空工具箱）。

### 9.4 降级

- 无 API Key / `MOCK_LLM=true` → Mock LLM  
- Milvus 不可用 → BM25 / 本地索引兜底（视实现路径）  
- Redis/MySQL 不可用 → 跳过对应层，继续后续

## 10. 文档识别

模块：`backend/services/doc_parser.py`  
工具：`parse_document`（可续接 `extract_quote_fields`、`doc_vs_requirement`）

| 输入 | 策略 |
|------|------|
| 文本型 PDF | pdfplumber 抽文本与表格 |
| 扫描 PDF / 文字过少 | 转图片后 `qwen-vl-plus` |
| 图片 png/jpg/webp… | 直接视觉识别 |
| `force_vision=true` | 强制视觉 |

上传：`POST /api/documents/upload` → 返回 `file_path` → 带入 `/api/assistant/chat`。

## 11. 数据模型与持久化

### 11.1 运行时 Store

默认 **JSON 文件**，目录 `storage/`（由 `config.storage_dir` 指定）：

| 文件/区域 | 内容 |
|-----------|------|
| `users.json` | 账号 |
| `sessions.json` | 登录 Token |
| `runtime.json` 等 | 询盘、审批、样品、跟进、报价、订单、客户、厂商、审计… |
| `kb_index.json` | 知识索引兜底（若有） |

种子数据：`data/seed/*.json`，首次或初始化时可灌入。

### 11.2 主要业务实体（概念）

- **Inquiry**：海外询盘；含 `pipeline`（Agent 中间结果：requirement、vendor_match、reply_draft…）  
- **Approval**：发送审批单  
- **Quotation / Order / Sample / Followup**  
- **Customer / Vendor**：档案；`related_*` 聚合关联单据  

> 注意：当前非多租户强隔离生产库；并发与备份能力有限，适合小团队内网试用。

## 15. API 一览

## 16. 扩展开发指南

### 16.1 新增一个工具

1. 在 `handlers.py` 或 `extended.py` 实现 `tool_xxx(**payload) -> dict`  
2. 在 `bootstrap_tools()` 里 `register_tool(AgentTool(...))`  
3. 把工具名加入对应 `domain_agents.py` 的 `tools` 列表  
4. 如需默认触发：改某个 `skills/*.yaml` 的 `tools` / `triggers`，或加新 Skill YAML  
5. 若有新 pipeline 字段：加入 `orchestrator.merge_pipeline` 白名单  
6. 重启 API；更新 [Agent与工具参数手册.md](./Agent与工具参数手册.md)

### 16.2 新增一个 Skill

1. 新增 `backend/agents/skills/<id>.yaml`  
2. 在 `SKILL_TO_AGENT` 映射到子 Agent  
3. 按需要插入 `router._RULE_ORDER`  
4. `reload_skills()` 或重启进程（loader 有 lru_cache）

### 16.3 新增前端页面

1. `views/Xxx.vue`  
2. `router.js` 注册路由  
3. `App.vue` 侧栏增加入口  
4. `api.js` 增加请求方法  

### 16.4 读代码推荐顺序

1. `run_api.py` → `config.py` → `api/app.py`（搜 `@app.post`）  
2. `frontend/src/router.js` → `Assistant.vue`  
3. `supervisor.py` → `domain_agents.py` → `skills/router.py`  
4. `orchestrator.py` → `handlers.py` / `extended.py`  
5. `services/store.py` → `storage/`  
6. `chat_assistant.py` → `knowledge_base.py`

## 17. 已知限制与路线图

### 17.1 当前限制（诚实清单）

| 项 | 现状 |
|----|------|
| 数据库 | JSON 文件，弱并发、弱备份 |
| 邮件 | 无真实 IMAP/SMTP 收发，询盘偏人工录入 |
| 生产部署 | 偏开发机 + 可选 Tailscale，非 K8s/高可用 |
| Agent | LLM 偶发抽风；写入 CRM 缺少强制二次确认 UI |
| 安全 | 适合内网；密钥与上传文件需自行管好 |
| 测试 | 自动化测试覆盖不足 |

### 17.2 建议演进方向

1. PostgreSQL/MySQL 替换 JSON Store  
2. 真实邮箱接入与询盘自动建档  
3. 写操作确认框 + 权限细粒度 + 操作回滚  
4. Docker Compose 一键（API + 前端 + Milvus + Redis + MySQL）  
5. 监控告警与备份策略  
6. 更完整的集成测试 / Agent 评测集
