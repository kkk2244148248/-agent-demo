## 1. 配置总表与可替代方案

配置加载：`backend/config.py` → `Settings`（Pydantic Settings）  
读取顺序：环境变量 ≈ `.env.local`（`env_file`）→ 代码默认值。  
API Key 额外扫描：`Apikey` / `APIKEY` / `ApiKey` / `API_KEY` / `DASHSCOPE_API_KEY` / `LLM_API_KEY`。

### 1.1 LLM / 视觉

| 配置字段 | 环境变量（典型） | 默认值 | 谁在用 | 可替代 |
|----------|------------------|--------|--------|--------|
| `llm_api_key` | `LLM_API_KEY` 或系统 `Apikey` | `""` | 全部真模型调用 | 换成其它 OpenAI 兼容服务的 Key |
| `llm_base_url` | `LLM_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `ChatOpenAI(base_url=…)` | **OpenAI** `https://api.openai.com/v1`；**DeepSeek** / **Moonshot** / **本地 vLLM/Ollama 的 OpenAI 兼容口**（需改 `llm_model`） |
| `llm_model` | `LLM_MODEL` | `qwen-plus` | 文本对话主模型 | `qwen-turbo`（更便宜更快）、`qwen-max`（更强）、`gpt-4o-mini`、`deepseek-chat` 等（须与 base_url 匹配） |
| `vision_model` | `VISION_MODEL` | `qwen-vl-plus` | `doc_parser._vision_recognize` | `qwen-vl-max`；或其它多模态 OpenAI 兼容视觉模型（需改调用代码若协议不同） |
| `mock_llm` | `MOCK_LLM` | `false` | `use_real_llm` 判定 | `true` → 全程 `MockChatModel`，不花 Key，适合联调 UI |

判定逻辑：

```text
use_real_llm = (not mock_llm) and bool(resolved_api_key)
```

无 Key 时自动走 Mock，不必改代码。

### 1.2 嵌入 / Milvus

| 配置字段 | 默认 | 谁在用 | 可替代 |
|----------|------|--------|--------|
| `bge_m3_model_path` | 本机 BGE-M3 目录 | `embedder.BGEMEmbedder` | 换路径到其它 BGE-M3 权重；**换模型族需改 `VECTOR_DIM` 与建表** |
| `use_local_bge` | `true` | 语义开关（实现以本地 FlagEmbedding 为主） | 未来可接云嵌入 API（需改 `embedder.py`） |
| `use_milvus` | `true` | `knowledge_base` 是否优先 Milvus | `false` → 走本地 BM25 兜底 |
| `milvus_host` | `127.0.0.1` | MilvusClient URI | 远程 Milvus / Zilliz Cloud（改 host/port 或改 URI 拼装） |
| `milvus_port` | `19530` | 同上 | 按实例端口 |
| `milvus_collection` | `gift_knowledge` | 集合名 | 新集合名；需重建索引 |
| `default_tenant_id` | `tenant_demo` | 检索 filter `tenant_id` | 多租户时按租户改 |

硬编码（改代码才能动）：

| 常量 | 位置 | 值 | 含义 / 替代注意 |
|------|------|-----|----------------|
| `VECTOR_DIM` | `milvus_client.py` | `1024` | BGE-M3 dense 维；换 bge-large-zh 等需同步改 dim |
| `ANN_EF` | 同上 | `64` | HNSW 查询 ef；可增大提高召回、降速 |
| HNSW `M` / `efConstruction` | 建索引 | `16` / `256` | 建库时参数；改后需重建集合 |
| sparse `drop_ratio_build` | 建索引 | `0.2` | 稀疏索引构建丢弃比 |
| `WeightedRanker(0.7, 0.3)` | hybrid_search | dense 0.7 / sparse 0.3 | 可改权重偏向关键词或语义 |
| child 召回倍率 | `knowledge_base._search_milvus` | `top_k * 3`（至少 8） | 先多取再 parent 去重 |

### 1.3 Redis

| 字段 | 默认 | 用途 | 可替代 |
|------|------|------|--------|
| `redis_host/port` | `127.0.0.1:6379` | 连接 | 云 Redis / 其它实例 |
| `redis_password` | `1234` | 认证；空则 `None` | 无密码设 `""` |
| `redis_db` | `2` | 逻辑库号 | 换 db 避免与其它项目冲突 |
| `redis_ttl_seconds` | `86400`（1 天） | 答案缓存 TTL | 缩短防脏缓存；`0` 需改代码支持 |
| `redis_key_prefix` | `gift_chat` | Key 前缀 | 多环境隔离 |

Key 格式：`{prefix}:{tenant}:qa:{sha256(normalize(query))[:32]}`  
`normalize`：小写、压缩空白。  
连接失败：标记 `_failed`，后续跳过缓存（不阻断主流程）。

## 2. LLM 工厂：模型路由与可替代

文件：`backend/core/llm_factory.py`

### 2.1 `agent_type` 合法值

当前全部映射到同一物理模型 `"default"` → `settings.llm_model`：

| agent_type | 典型调用方 | 典型 temperature | 用途 |
|------------|------------|------------------|------|
| `requirement` | `tool_parse_requirement`、抽报价字段 | `0` | 结构化需求 / 字段抽取 |
| `vendor_match` | `tool_search_vendors` | `0` | 厂商匹配 JSON |
| `compare` | `tool_compare_quotes`、成本粗算 | `0` | 比价 / 估价 JSON |
| `reply` | 海外回复、润色、跟催 | `0.3` | 邮件文案（略创意） |
| `factory_brief` | 询厂话术、打样简报 | `0.2` | 中文厂端文案 |
| `intent` | 总控/Skill 路由、CRM 抽取、待办抽取 | `0` | 分类 / JSON 意图 |
| `quote` | （预留） | — | 报价相关 |
| `followup` | （预留） | — | 跟进相关 |
| `summarize` | `kb_search`、`chat_assistant` RAG 回答 | `0.2` | 基于资料总结 |

**未在表中的 type** → `ValueError: 未知 agent_type`。

### 2.2 实例化方式

```python
ChatOpenAI(
  model=settings.llm_model,
  api_key=settings.resolved_api_key,
  base_url=settings.llm_base_url,
  temperature=temperature,
)
```

缓存 Key：`{llm_model}_{temperature}_{api_key后8位}`。

### 2.3 如何「一个场景换更强模型」（现状与改造点）

**现状**：所有 `agent_type` 共用一个 `llm_model`，无法在配置里按场景拆模型。

**可替代改造（推荐做法）**：

1. 把 `_AGENT_MODEL_ROUTING` 的值从 `"default"` 改成真实模型名，例如：
   - `"intent": "qwen-turbo"`
   - `"compare": "qwen-max"`
   - `"reply": "qwen-plus"`
2. 或在 `Settings` 增加 `llm_model_intent` / `llm_model_reply` 等字段，工厂按 type 读取。  
3. 视觉已独立：`vision_model`，与文本模型解耦。

### 2.4 可整体替换的后端厂商

| 方案 | `llm_base_url` 示例 | `llm_model` 示例 | 注意 |
|------|---------------------|------------------|------|
| 通义 DashScope（当前） | `.../compatible-mode/v1` | `qwen-plus` | 默认 |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | Key 换 OpenAI；视觉另议 |
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` | |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:14b` | 需 OpenAI 兼容插件 |
| Azure OpenAI | Azure endpoint | deployment 名 | 可能要改 `api_key` 头（LangChain 另有类） |

Mock：`MOCK_LLM=true` 或无 Key → `backend/core/mock_llm.py`。

## 3. 向量嵌入与 Milvus 检索参数

### 3.1 BGE-M3（`embedder.py`）

| 参数 | 值 | 说明 |
|------|-----|------|
| 加载类 | `FlagEmbedding.BGEM3FlagModel` | |
| `use_fp16` | `torch.cuda.is_available()` | 有 GPU 用半精度 |
| `encode` batch_size | 默认 `8`；query 用 `1` | |
| `max_length` | `8192` | |
| `return_dense` | `True` | 1024 维 |
| `return_sparse` | `True` | lexical_weights |
| `return_colbert_vecs` | `False` | 未用 ColBERT |

**可替代嵌入**：

| 方案 | 改动点 |
|------|--------|
| 继续 BGE-M3，换磁盘路径 | 只改 `BGE_M3_MODEL_PATH` |
| bge-base / 其它维度 | 改 embedder + `VECTOR_DIM` + **重建 Milvus 集合** |
| 云 API 嵌入（OpenAI text-embedding-3） | 重写 `encode`；稀疏向量需另方案或改纯 dense 检索 |
| 仅 BM25 | `USE_MILVUS=false`，走 `_search_local` |

### 3.2 Hybrid 检索（`milvus_client.hybrid_search_children`）

| 参数 | 值 |
|------|-----|
| dense 字段 | `embedding`，COSINE，`ef=64` |
| sparse 字段 | `sparse_embedding`，IP |
| filter | `tenant_id == "{tenant}" and chunk_level == "child"` |
| ranker | `WeightedRanker(0.7, 0.3)` |
| 回填 | 返回 `parent_content` |

`knowledge_base.search(query, top_k=4)`：  
Milvus 路径内部 `hybrid_search_children(..., top_k=max(top_k*3, 8))` 再按 parent 去重截断到 `top_k`。

### 3.3 知识检索调用点的 top_k

| 调用方 | top_k |
|--------|-------|
| `tool_search_vendors` | **5**（写死） |
| `tool_kb_search` | `payload.top_k` 或 **4** |
| `POST /knowledge/search` | Body `top_k`，默认 4，范围 **1–12** |
| `chat_assistant` RAG | `settings.chat_rag_top_k` 默认 **4** |

## 4. Redis 缓存与 MySQL FAQ

### 4.1 Redis

- 模块：`services/redis_cache.py`  
- 超时：`socket_connect_timeout=2`，`socket_timeout=2`  
- 存：`json.dumps` 含 `answer` 的 dict；TTL=`redis_ttl_seconds`

### 4.2 FAQ

- 模块：`services/faq_mysql.py`  
- `best_above_threshold(q)`：先 `search(top_k=1)`，再比 `confidence >= faq_bm25_confidence` 且分数过 `faq_bm25_min_score`  
- `tool_faq_lookup`：优先 threshold 命中；否则可退到 `search(top_k=1)` 弱命中

**可替代**：把阈值写进管理后台；或换向量 FAQ；或关掉 MySQL 只走 RAG。

## 5. HTTP API 请求体字段级说明

鉴权：除 `/api/health`、`/api/auth/login` 外，Header：

```http
Authorization: Bearer <token>
```

前端通过 Vite 代理：`/api` → `http://127.0.0.1:8000`（`frontend/vite.config.js`）。

### 5.1 `POST /api/assistant/chat` ← 对话助手主入口

Body 模型：`AssistantChatBody`

| 字段 | 类型 | 必填 | 约束/默认 | 传到哪里 |
|------|------|------|-----------|----------|
| `message` | string | **是** | 1–4000 字 | `run_supervisor_desk` 的用户话；工具里常作 `query` |
| `inquiry_id` | string | 否 | `""` | 有则加载询盘并合并 context；工具跑完可写回 `pipeline` |
| `subject` | string | 否 | | 询盘主题；覆盖/补全 inquiry |
| `body` | string | 否 | | 询盘正文 |
| `customer_name` | string | 否 | | 客户名 |
| `country` | string | 否 | | 国家/市场 |
| `file_path` | string | 否 | 上传接口返回路径 | `context.file_path` → `parse_document` |
| `force_vision` | bool | 否 | `false` | 强制视觉 OCR |

**响应关键字段（逻辑）**：`answer`, `supervisor`, `agent_plan`, `invoked_tools`, `pipeline`, `actions`/`nav_links`, `layers`…

### 5.2 `POST /api/agents/run`

`AgentRunBody`：

| 字段 | 说明 |
|------|------|
| `user_goal` | 意图话术（路由用） |
| `tools` | **可选**；若传入则按该列表执行（跳过自动选工具） |
| `inquiry_id` | 绑定询盘 |
| `query/subject/body/customer_name/country` | 上下文 |
| `requirement` / `vendor_match` / `compare` / `pipeline` | **透传中间结果**，便于只跑下游工具 |

### 5.3 `POST /api/agents/{tool_name}`

单工具执行；上下文同 `AgentRunBody` 可传字段。`tool_name` 必须是已 `register_tool` 的名字。

### 5.4 `POST /api/inquiries/{id}/process`

`ProcessBody`：`subject/body/customer_name/country/user_goal/tools?`  
内部：`run_inquiry_pipeline`（`trade/graph.py`），结果写入 inquiry.pipeline。

### 5.5 `POST /api/chat/ask`

`ChatAskBody`：

| 字段 | 约束 |
|------|------|
| `question` | **必填** 1–2000 |
| `inquiry_id/subject/body/customer_name/country` | 可选上下文 |

### 5.6 `POST /api/knowledge/search`

| 字段 | 约束 |
|------|------|
| `query` | 必填 |
| `top_k` | 默认 4，**ge=1, le=12** |

### 5.7 业务 Body 速查

**SampleBody**：`id?, inquiry_id, customer_name, vendor_id, vendor_name, product, color, color_code, material, size_spec, finish, logo_process, logo_position, sample_qty, sample_fee, tracking_no, status="待打样", eta, notes`

**CustomerBody**：`name*` + country/contact/email/phone/channel/tags/priority/preferences/memo/notes/地址/网站/时区/付款条款/偏好贸易术语/颜色材料…

**VendorBody**：`name*` + region/contact/联系方式/categories/colors/materials/finishes/logo_processes/交期/付款/certifications/`quality_score=3`/产能/strengths/moq_note/price_note/`active=true`…

**InquiryBody**：客户与邮件字段 + qty/target_price/currency=`USD`/incoterms=`FOB`/destination/deadline/产品规格/priority/source_channel…

**QuotationBody**：inquiry/customer/vendor + currency/incoterms/valid_until/status=`draft`/total/notes/`lines[]`（QuoteLine：product/color/material/qty/unit_price/moq/lead_days/notes）

**OrderBody**：关联 id + 产品规格 + qty/unit_price/currency/deposit/status=`待定金`/etd/tracking_no/notes

**FollowupBody**：customer/inquiry + due_date/reason/suggested_action/priority=`medium`/status=`open`

**ApprovalDecideBody**：`approve: bool`, `final_text: str=""`

**CreateUserBody**：`username*, password*, name*, role="外贸业务员", email, is_admin=false, can_approve=false`

**LoginBody**：`username*, password*`

## 6. 工具级参数手册（全量）

执行引擎：`orchestrator.run_selected_tools` → `registry.call_tool(name, **ctx)`  
`ctx` = 请求上下文字段 + 当前 `pipeline` 展开字段。  
公共读取：`handlers._ctx(payload)` → inquiry 字段 + `requirement/vendor_match/compare/retrieved_*/reply_draft/factory_brief/query`。

下列「内部调用」列给出**真实函数 / 模型 agent_type / 温度**。

### 6.1 寻源

#### `parse_requirement`

| 项 | 内容 |
|----|------|
| 实现 | `handlers.tool_parse_requirement` |
| 入参（关键） | `subject`, `body`；可选 `customer_name`, `country` |
| 内部 | `get_llm("requirement", temperature=0)` + `REQUIREMENT_*` prompts |
| 产出 | `requirement`, `intent`, `intent_detail`, `summary` |
| 可替代 | 换更强模型做结构化；或规则/表单 UI 代替 LLM |

#### `search_vendors`

| 项 | 内容 |
|----|------|
| 实现 | `handlers.tool_search_vendors` |
| 入参 | `query` **或** `requirement.search_query/product_summary/category` **或** `subject`+`body`；全空则 `"礼品 厂商"` |
| 内部 | `get_knowledge_base().search/format_context(top_k=5)` → `get_llm("vendor_match", 0)` |
| 产出 | `vendor_match`, `retrieved_context`, `retrieved_sources`, `summary` |
| 可替代 | 只查 `store.list_vendors` 关键词（无 RAG）；或接 1688 API |

#### `rank_vendors`（extended）

| 项 | 内容 |
|----|------|
| 入参 | `vendor_match.matched_vendors`；否则用 `query` 扫 Store 厂商 |
| 规则分 | 基础 match_score×100；数量&lt;MOQ -25；交期&gt;45 -10；≤25 +5；风险备注 -15；停用 -40 |
| 产出 | `vendor_ranking`, `vendor_shortlist`（前 3） |
| 可替代 | 学习排序模型；或人工权重配置化 |

#### `compare_quotes`

| 项 | 内容 |
|----|------|
| 硬依赖 | `requirement` **或** `vendor_match` 至少一个，否则 `error` |
| 内部 | `get_llm("compare", 0)` + `COMPARE_*` |
| 产出 | `compare`, `quote_draft`（取首选 option）, `summary` |
| 可替代 | 接真实工厂报价表；禁止 LLM 估假价（合规） |

#### `estimate_cost`（extended）

| 项 | 内容 |
|----|------|
| 优先 | 读 `compare.options` 算数量×单价 |
| 否则 | 规则默认区间，或 `get_llm("compare", 0)` 估 USD 区间 |
| 产出 | `cost_estimate.lines` + disclaimer |
| 可替代 | 成本核算表 / ERP |

#### `vendor_risk_check`（extended）

| 项 | 内容 |
|----|------|
| 入参 | matched / compare 的 vendor_id，或 query 中 `V-xxx` |
| 内部 | `store.get_vendor`；规则扫备注/认证字段 |
| 产出 | `risk_report[]`（level: low/medium/high/unknown） |

### 6.2 沟通

| 工具 | 关键入参 | 内部 | 产出 | 依赖 |
|------|----------|------|------|------|
| `draft_client_reply` | subject/body/customer；requirement+compare 更佳 | `get_llm("reply", 0.3)` | `reply_draft` | 无比价也能写，质量差 |
| `polish_reply` | **必须已有** `reply_draft`；query 含「短/强硬/软」定 tone | `get_llm("reply", 0.3)` | 覆盖 `reply_draft` | 先 draft |
| `draft_followup_mail` | 客户与需求/比价摘要 | `get_llm("reply", 0.3)` | `followup_mail_draft`（兼写 reply_draft） | |

## 7. Prompt 输出契约（JSON schema 语义）

### 7.4 可替代 Prompt 策略

- 把 JSON schema 改为 `with_structured_output`（工厂已有 `get_structured_llm`，工具侧尚未全面启用）  
- 多语言：改 SYSTEM 要求输出语言  
- 更严「禁止编造厂商 ID」：加检索到的 ID 白名单进 prompt

## 11. 替换决策速查表（场景向）

| 目标 | 优先改什么 | 风险 |
|------|------------|------|
| 更便宜 | `LLM_MODEL=qwen-turbo`；提高 FAQ 命中少打 RAG | 质量下降 |
| 更强推理 | `qwen-max` / GPT；intent/compare 单独路由 | 费用↑延迟↑ |
| 离线演示 | `MOCK_LLM=true` | 答案固定假数据 |
| 无 GPU | BGE 自动 fp32；或关 Milvus 用 BM25 | 检索变弱 |
| 无 Milvus | `USE_MILVUS=false` | 仅本地 BM25 |
| 换嵌入模型 | 路径+维度+重建集合 | 旧向量全废 |
| 正式库 | 重写 Store → SQL | 工作量大，但必做 |
| 真邮件 | 新服务 IMAP/SMTP → create_inquiry | 产品缺口 |
| OCR 国产化 | `doc_parser` 换 PaddleOCR | 视觉 Key 可省 |
